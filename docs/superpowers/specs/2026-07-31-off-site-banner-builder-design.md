# Off-site Banner Builder — 설계

작성 2026-07-31 · 상태: 승인됨, 구현 전

## 배경

지금 앱의 3개 빌더는 모두 **마켓플레이스 안쪽**(Shopee·Lazada 스토어 페이지, Lazada 검색 배너)에 들어갈 자산을 만든다.
Meta와 PMax는 그 바깥에서 트래픽을 끌어오는 매체인데, 여기 쓸 배너는 지금 만들 방법이 없다.

문제는 같은 캠페인을 정사각(1200×1200)과 와이드(1200×650) 두 비율로 내야 한다는 것이다.
비율마다, 제품마다 따로 그리면 한 캠페인 안에서 문구와 톤이 갈라진다.

**목표: KV를 한 번 구성하면 모든 비율로 자동 파생되고, 어긋나는 비율만 손으로 잡는다.**

## 결정 사항

| 항목 | 결정 |
|---|---|
| KV 구조 | **레이어 조합** (완성 이미지 크롭 아님) |
| 사이즈 | **1200×1200, 1200×650** 2개 고정. 매체 구분 없음 |
| 화면 구성 | **3단계 위저드** (`WizardBreadcrumb` 재사용) |
| 사이즈별 조정 | 카드 클릭 → override (위치·크기·표시여부만) |
| 폰트 | 빌더 전체 하나. 기존 `BrandFontSelector` 재사용 |
| 출력 규모 | 제품 수 × 2 |

**단일 화면 → 3단계 위저드로 변경 (2026-07-31).** 처음엔 "KV 하나 → 비율 여러 장"으로 보고 단일 화면을 제안했으나,
실제 운영은 **배경·카피를 고정한 채 제품을 갈아끼우는** 방식이었다.
결과물이 `제품 수 × 2`로 늘어나 Thumbnail Bulk와 같은 성격이 되므로 단계를 나눈다.

**폰트 선택기를 넣는 이유:** 처음엔 "Off-site는 LG 자체 매체이므로 LGEI 고정"으로 제안했으나,
법인이 Shopee/Lazada 폰트 사용을 요청. 광고 클릭 후 도착하는 스토어와 폰트가 이어지는 이점도 있다.

## 플로우 — 3단계

```
1. Campaign            2. Product Blocks        3. Review & Download
┌────────────────┐    ┌────────────────┐       ┌────────────────┐
│ 배경 이미지 업로드│    │ ┌────────────┐ │       │ 제품1  □정사각 □와이드│
│ 로고            │ →  │ │LG.com URL  │ │  →    │ 제품2  □정사각 □와이드│
│ 카피·가격·CTA   │    │ │ ↓          │ │       │ 제품3  □정사각 □와이드│
│ 디스클레이머     │    │ │누끼·포디움  │ │       │                │
│                │    │ │크기·엠블럼  │ │       │   [ ZIP ↓ ]    │
│                │    │ └────────────┘ │       │                │
│                │    │ [+ 블록 추가]  │       │                │
└────────────────┘    └────────────────┘       └────────────────┘
```

| 슬롯 | 1단계 캠페인 | 2단계 제품 블록 |
|---|---|---|
| 배경 이미지 | ✅ **업로드** | |
| 로고 (LG + 캠페인) | ✅ | |
| 헤드/서브 카피 · 가격 · CTA · 디스클레이머 | ✅ | |
| 제품 누끼 | | ✅ **LG.com URL fetch** |
| 포디움 | | ✅ **업로드** |
| 제품 크기 · 포디움 위 높이 | | ✅ |
| 엠블럼 (우상단, 이미지) | | ✅ |

**포디움은 제품별이다.** 냉장고와 TV는 다른 단이 필요하고, 제품이 단 위에 어떻게 앉는지는
그 제품을 화면에 띄워야만 판단된다. 그래서 "이 제품을 어떻게 보여줄까"에 해당하는 것
(누끼·포디움·크기·엠블럼)이 전부 한 블록에 모인다.

레이어 순서는 **배경 → 포디움 → 제품**. 제품이 단 위에 서 있는 형태다.

**이미지 입력 경로가 둘로 갈린다** — 배경·포디움은 직접 업로드, 제품은 LG.com URL fetch.
기존 빌더들이 URL fetch 위주였던 것과 다른 지점이다.

**2단계는 블록 반복 UI.** Thumbnail Bulk의 URL 입력 방식을 재사용한다
(URL → `/api/crawl-page` → 이미지 선택 → `aiBgRemoval` → 크롭). 블록 하나 = 제품 하나.

**3단계는 제품별 행**으로 편다 — 세로축 제품, 가로축 사이즈 2개. 카드 제외(체크 해제)와 override,
다운로드를 이 화면에서 모두 처리한다.

## 배너 해부 구조

레이어는 자유 목록이 아니라 **앵커가 고정된 해부 구조**다. 이 덕분에 비율이 바뀌어도 배치 규칙이 흔들리지 않는다.

```
┌──────────────────────────────┐
│ [LG+캠페인로고]        [뱃지] │  ← 좌상단 / 우상단 앵커
│          ┌────────┐          │
│          │ 제품누끼 │          │  ← 중앙, 남는 공간을 전부 흡수
│          └────────┘          │
│         ▁▁▁ 단상 ▁▁▁          │
│          헤드카피             │
│          서브카피             │  ← 중앙정렬 텍스트 블록
│          가격정보             │
│         [ CTA 버튼 ]          │  ← 하단 고정
│  디스클레이머                  │  ← 최하단
└──────────────────────────────┘
```

| 슬롯 | 앵커 | 입력 | 재사용 |
|---|---|---|---|
| 로고 | 좌상단 | LG 로고(고정) + 캠페인 로고(선택) | 에셋 라이브러리 |
| 뱃지 | 우상단 | *미정 — 텍스트/이미지* | |
| 제품 누끼 | 중앙 (가변) | URL fetch → 배경제거 → 크롭 | `aiBgRemoval.ts`, `ImageCropModal`, `/api/crawl-page` |
| 단상 | 제품 하단 | PNG 에셋 | 라이브러리 `podium` 카테고리 신설 + 직접 업로드 |
| 헤드/서브/가격 | 중앙정렬 스택 | 텍스트 | |
| CTA 버튼 | 하단 고정 | 텍스트 + 스타일 | |
| 디스클레이머 | 최하단 | 텍스트 | |

**높이 가변분은 제품 누끼 영역이 전부 흡수한다.** 나머지는 가장자리에 붙어 있거나 내용만큼만 차지하므로,
정사각에서 남는 세로 공간이 갈 곳이 하나뿐이다. 사이즈별 좌표표를 따로 두지 않아도 되는 근거다.

각 슬롯은 house 컨벤션대로 pill 토글로 on/off (체크박스 금지).

## 사이즈

Meta와 PMax가 같은 규격을 받으므로 **매체 구분이 없다**. 파일명에도 매체 세그먼트를 넣지 않는다.

| id | 픽셀 | 비율 | 배치 |
|---|---|---|---|
| `1200x1200` | 1200×1200 | 1:1 | 세로 스택 |
| `1200x650` | 1200×650 | 1.85:1 | 좌우 분할 |

`components/offsite/offsiteSizes.ts`의 배열이 유일한 정의다. 사이즈 추가는 행 하나 추가로 끝난다.

## 비율별 배치 규칙

좌표를 사이즈마다 손으로 짜지 않고 **규칙 두 개로 파생**시킨다. 사이즈가 추가돼도 코드 변경 없이 붙는다.

```
     1200×1200                  1200×650 (와이드)
  ┌──────────┐             ┌──────────────────────┐
  │[로고] [뱃]│             │[로고]          [뱃지] │
  │  제품     │             │ ┌────┐  헤드카피      │
  │  ▁▁▁     │      vs     │ │제품 │  서브·가격     │
  │  헤드     │             │ └────┘  [ CTA ]      │
  │  [CTA]   │             │ 디스클레이머           │
  └──────────┘             └──────────────────────┘
     세로 스택                  좌우 분할
```

- **세로/정사각** (w/h < 1.2) — 위 해부 구조 그대로 세로 스택
- **가로형** (w/h ≥ 1.2) — 좌우 분할. 로고·뱃지·디스클레이머 앵커는 유지
- 가로형은 **좌우 반전 토글** 제공 (기본: 제품 왼쪽). 캠페인마다 다를 수 있어 코드로 고정하지 않는다

헤드카피는 자동 축소 맞춤. 측정은 활성 브랜드 폰트 기준으로 해야 한다
(`getActiveMeasureStack()` — 폰트마다 글자폭이 달라 LGEI 기준으로 재면 다른 폰트에서 잘린다).

## 상태 모델

앱에 선례가 없는 구조라 새로 만든다.

```
campaign                    ← 1단계 (배경·로고·카피·가격·CTA·고지문)
products[]                  ← 2단계 (누끼·포디움·크기·엠블럼)
overrides[productId][sizeId]   ← 3단계 카드별 조정
```

렌더 대상 한 장 = `campaign + products[i] + overrides[i][sizeId]`.

- **1·2단계를 수정하면 관련 override를 비운다.** 안 그러면 "앞 단계에서 바꿨는데 저 카드만 안 바뀐다"가 나온다
- override가 있는 카드엔 ✎ 배지 + 되돌리기 버튼
- **override 허용 범위는 위치·크기·표시여부로 제한.** 카피 내용까지 사이즈별로 갈리면 자동 베리에이션의 의미가 사라진다

## Export

기존 빌더 파일명 컨벤션을 따른다. 기본 폰트(`lg`)일 땐 폰트 태그를 붙이지 않는다.

```
01-{model}-1200x1200-shopee-260731.png
01-{model}-1200x650-shopee-260731.png
```

- 제품별 폴더 또는 파일명 prefix로 묶는다 (Thumbnail Bulk의 `${model}/` 방식 참고)
- 제품 1개당 2파일 — 제품이 많아지면 진행률 UI 필요
- export 직전 `ensureBrandFontLoaded(fontId)` 필수 — 2회 워밍업은 이미지만 캐싱하므로 폰트가 폴백으로 박힐 수 있다
- 기존 2회 워밍업 + 3번째 `cacheBust: true` 패턴 유지

## 드래프트

다른 빌더와 동일하게 IndexedDB. `builder: 'off-site'` 키를 새로 추가.
payload = `campaign + products[] + overrides + fontId`. `fontId`는 optional로 두고 로드 시 `'lg'` 폴백
(`schemaVersion`은 올리지 않는다 — 올리면 기존 드래프트가 전부 "newer version" 경고로 막힌다).

## 앱 통합

기존 패턴대로 한 칸씩 늘리면 된다.

- `NavRailKey` — `'off-site'` 추가 (`components/NavRail.tsx`)
- `AppStep` — `'off-site'` 추가 (`app/App.tsx`)
- 홈 카드 4번째 추가 (`components/ContentBuilderHome.tsx`)
- 신규: `components/offsite/` — 위저드 3단계 + 배너 렌더러 + `offsiteSizes.ts`
- 재사용: `WizardBreadcrumb`, `AssetLibraryModal`, `ImageCropModal`, `aiBgRemoval.ts`, `/api/crawl-page`
- 신규: `drafts/offsitePayload.ts`

## 미정 (구조에 영향 없음, 정해지는 대로 채움)

- **엠블럼 소스** — 이미지인 것은 확정. 에셋 라이브러리 등록인지 매번 업로드인지 미정
- **캠페인 로고 소스** — 라이브러리인지 매번 업로드인지
- **단상 에셋** — 실물 PNG 아직 없음

## 검증

- 1단계 편집이 모든 제품·양쪽 사이즈에 반영되는지
- 제품을 추가/삭제하면 3단계 그리드 행이 따라 늘고 주는지
- 1200×1200은 세로 스택, 1200×650은 좌우 분할로 나오는지, 좌우 반전 토글이 먹는지
- 카드 override 후 전역 편집 시 override가 풀리는지
- 폰트 3종 전환 시 레이아웃이 세로로 밀리지 않는지 (기존 line-box override 덕에 유지돼야 함)
- 제품 N개 → ZIP 2N파일로 전개되는지, 파일명 규칙이 맞는지
- 드래프트 저장 → 새로고침 → 복원
- **PNG에 폰트가 실제로 박히는지** — 화면은 맞는데 export만 폴백인 것이 이 앱의 대표 실패 모드
